# Farm Registry Python Tools

> **API status:** local, testable synthetic demo. The API is not deployed and
> no live endpoint is claimed. `render.yaml` is a deployment blueprint only.

A compact FastAPI data service for demonstrating farm, field and field-activity
workflows across the Farm Registry portfolio. It exposes typed REST contracts,
GeoJSON parcel validation, deterministic demo data and an offline-retry-safe
observation flow without external services or production infrastructure.

## What the demo covers

| Workflow | Implemented behavior |
| --- | --- |
| Farms and fields | List farms, open a farm with its fields, and filter fields by farm, status or crop. A legacy parcel projection remains available for the web client. |
| Parcel validation | Validate 2D WGS84 GeoJSON `Polygon` and `MultiPolygon` geometry and calculate geodesic area in square metres, including holes and multipart geometry. |
| Tasks | Filter tasks or create one after verifying that both IDs exist and that the field belongs to the selected farm. |
| Observations | Filter observations or create one with a required `client_action_id`. Replaying the same action returns the existing observation instead of inserting a duplicate. |
| Sync events | Read the synthetic event stream. New tasks and first-time observations append `created` events; replayed observation actions do not. |
| Demo reset | Delete runtime changes and restore the same seeded dataset and counts through `POST /demo/reset`. |

Created resources receive `SYN-` IDs. Unknown resource IDs produce controlled
`404` responses; invalid request schemas produce `422`. Malformed parcel
geometry is represented as `valid: false` instead of surfacing an internal
server error.

## API surface

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/health` | Service health response |
| `GET` | `/parcels` | Legacy web contract: `id`, `farmer`, `area`, `status`, `crop`, `center` |
| `POST` | `/validate/parcel` | GeoJSON validation and WGS84 geodesic area calculation |
| `GET` | `/farms` | Farm list |
| `GET` | `/farms/{farm_id}` | Farm detail with its fields |
| `GET` | `/fields` | Field list with optional `farm_id`, `status` and `crop` filters |
| `GET` | `/fields/{field_id}` | Field detail |
| `GET` | `/tasks` | Tasks with optional `status`, `farm_id` and `field_id` filters |
| `POST` | `/tasks` | Create a validated farm/field task |
| `GET` | `/observations` | Observations with optional `field_id` and `status` filters |
| `POST` | `/observations` | Idempotent observation creation by `client_action_id` |
| `GET` | `/sync/events` | Synthetic synchronization/audit events |
| `POST` | `/demo/reset` | Restore deterministic fixture data |

Interactive OpenAPI documentation is generated by FastAPI at `/docs`. Local
reference captures are included for [desktop](docs/screenshots/openapi-desktop.png)
and [mobile](docs/screenshots/openapi-mobile.png); they are screenshots, not
evidence of a live service.

## Architecture and portfolio integration

```text
Farm Registry Web ───────┐
                         ├── FastAPI + Pydantic contracts
Farm Registry Mobile ────┘              │
                                        ├── Shapely + pyproj (GeoJSON validation)
                                        └── DemoRepository ── SQLite :memory:
```

- [`app/main.py`](app/main.py) owns the HTTP routes, Pydantic request/response
  models, explicit CORS policy and parcel geometry validation.
- [`app/repository.py`](app/repository.py) owns the SQLite schema, synthetic
  fixtures, filtering, writes, event creation and reset behavior. A lock guards
  access to the single shared connection inside the process.
- [Farm Registry Web](https://github.com/luciandanileico94-dev/farm-registry-web)
  is the related browser client repository. This API preserves its parcel list
  shape and exposes parcel validation and registry workflows.
- [Farm Registry Mobile](https://github.com/luciandanileico94-dev/farm-registry-mobile)
  is the related mobile client repository. Tasks, observations,
  `client_action_id` idempotency and sync events form the intended mobile-facing
  contract.

The client applications are separate repositories, not embedded modules or
runtime dependencies here. This repository provides their demo API contracts;
it does not prove that either client is currently connected to a deployed
instance.

## Deterministic demo storage

The API deliberately uses **in-memory SQLite demo storage** through Python's
standard-library `sqlite3` module. One repository instance is seeded during
application import. Data survives only for the lifetime of that process and is
lost on process restart; it is not production persistence.

The initial dataset is deterministic:

| Resource | Seed count |
| --- | ---: |
| Farms | 6 |
| Fields | 12 |
| Tasks | 12 |
| Observations | 10 |
| Sync events | 12 |

`POST /demo/reset` clears all five tables and reseeds those exact fixtures. The
endpoint is intentionally available for repeatable demonstrations and tests,
not for a production registry.

## Local setup

Python 3.11 or newer is required.

```bash
python -m venv .venv
. .venv/bin/activate
python -m pip install -e '.[dev]'
uvicorn app.main:app --reload
```

Then open `http://127.0.0.1:8000/docs` or check the service directly:

```bash
curl http://127.0.0.1:8000/health
curl http://127.0.0.1:8000/farms
curl -X POST http://127.0.0.1:8000/demo/reset
```

### CORS

By default, CORS accepts the exact local Vite origins on ports `5173` and
`4173` for both `localhost` and `127.0.0.1`. Credentials are disabled, methods
are limited to `GET`, `POST` and `OPTIONS`, and wildcard origins are ignored.

For another environment, provide a comma-separated allowlist:

```bash
export FARM_REGISTRY_CORS_ORIGINS='https://web.example.test,https://preview.example.test'
uvicorn app.main:app --reload
```

## Verification

Install the development dependencies, then run the same checks defined in
[`pyproject.toml`](pyproject.toml) and [GitHub Actions](.github/workflows/ci.yml):

```bash
python -m pip install -e '.[dev]'
ruff check .
pytest -q
```

The tests cover health and CORS behavior, the legacy web response shape,
GeoJSON geometry and geodesic area validation, deterministic seed counts,
filters, farm/field task integrity, observation idempotency, safe unknown IDs,
seeded sync-event counts and reset behavior.

## Technology

- Python 3.11+
- FastAPI and Uvicorn
- Pydantic 2 request and response models
- SQLite via Python `sqlite3`, in memory only
- Shapely for GeoJSON geometry parsing and topology checks
- pyproj for WGS84 geodesic area calculation
- pytest, FastAPI TestClient/httpx and Ruff for verification
- GitHub Actions for `ruff check .` and `pytest -q`
- Render Blueprint configuration in `render.yaml`

## Data and security boundary

This is a synthetic/public portfolio demo. Every fixture is invented and uses
the `SYN-` namespace. The repository contains no secrets, credentials,
authentication integration, private GPS coordinates, cadastral identifiers,
real client records or production registry data. The displayed names, regions,
areas and coordinates are test values only.

There are no MPass, MConnect, cadastre, government-registry or other external
API integrations. Do not load private or production data into this demo; it has
no authentication or production access-control layer.

## Render status

[`render.yaml`](render.yaml) defines a free Python web-service blueprint named
`farm-registry-api-demo`, with `pip install .`, Uvicorn, `/health`, Python 3.12
and a manually supplied `FARM_REGISTRY_CORS_ORIGINS` value.

**The Render service has not been deployed.** A repository owner must connect
the repository to Render, create/confirm the Blueprint and set the allowed
origins. No live URL or deployment availability is asserted here. Even if
deployed from this blueprint, the in-memory database resets on process restart
and remains suitable only for a disposable demo.
